# PRD0 — 译点点

> 产品需求文档 v0。描述产品要做什么、用户怎么用、首版范围。
> 技术实现细节见 ARCHITECTURE.md、DECISIONS.md。

## 产品一句话

**译点点**：在任意网页上选中文字，弹框即译，即解。

## 核心用户流程

```
用户在任意网页上选中一段文字
        │
        ▼
悬浮框出现在选中文字附近，默认显示「翻译」tab 的结果（流式逐字输出）
        │
        ▼
用户可点击顶部 tab 切换到「解释」
        │
        ▼
结果流式输出完成后，用户可阅读、复制，或点击外部 / 按 Esc 关闭悬浮框
```

## 场景定义

### 场景 1：翻译

- **触发**：用户选中文字后悬浮框默认展示翻译结果
- **行为**：将选中文本翻译为用户配置的「目标语言」（默认中文）
- **输出**：纯文本译文，流式逐字显示

### 场景 2：解释

- **触发**：用户在悬浮框顶部 tab 切换到「解释」
- **行为**：用中文解释选中词/短语/概念的含义、背景、用法
- **输出**：纯文本解释（不含 Markdown），流式逐字显示

### 首版不做

- 「总结」场景（prompts 目录预留但暂不实现）
- 右键菜单触发（`contextMenus` 权限预留但暂不实现）
- 快捷键触发（`shortcutEnabled` 配置预留但暂不实现）
- 翻译历史记录（默认关闭，storage schema 预留）
- 多轮追问 / 对话

## 悬浮框交互规格

### 布局

```
┌─────────────────────────────────┐
│  [翻译]  [解释]          [✕]   │  ← tab 栏 + 关闭按钮
├─────────────────────────────────┤
│                                 │
│  流式内容区域                    │  ← 最大高度 300px，超出滚动
│  （逐字追加，自动滚底）           │
│                                 │
├─────────────────────────────────┤
│  [复制]              [重试]     │  ← 底部操作栏（done/error 时显示）
└─────────────────────────────────┘
```

### 行为规则

- **位置**：基于 `Range.getBoundingClientRect()` 定位在选中文字下方/附近
- **关闭方式**：Esc 键、点击悬浮框外部、点击 ✕ 按钮
- **滚动**：流式内容自动滚到底部；用户手动向上滚动后暂停自动滚动，避免抢夺滚动位置
- **状态机**：`idle` → `streaming`（逐字追加）→ `done` / `error`
- **中断**：关闭悬浮框 / 切换 tab / 选中新文本时，立即 abort 当前流式请求
- **Tab 切换**：用户从一个 tab 切换到另一个时，立即清空内容区并显示 loading 状态（可加 ~150ms 淡出过渡避免突兀），然后发起新请求流式填充。不保留旧 tab 的结果——tab 标签本身已说明当前在等什么，保留旧内容反而造成认知矛盾
- **错误**：展示可读错误信息 + 重试按钮；不卡在 loading 状态

### 技术约束

- 使用原生 DOM + Shadow DOM，不引入 React 等框架
- 不修改宿主页面全局样式
- 处理页面滚动、`transform` 等导致的定位偏移
- 处理 iframe 场景（至少不报错）

## 用户配置项

| 配置项            | 默认值     | 说明                                          |
| ----------------- | ---------- | --------------------------------------------- |
| `activeProvider`  | `deepseek` | 当前使用的大模型厂商                          |
| `apiKeys`         | 空         | 各厂商的 API Key，仅存 `chrome.storage.local` |
| `targetLang`      | `中文`     | 翻译目标语言                                  |
| `shortcutEnabled` | `true`     | 是否启用快捷键（首版预留，不实现）            |

配置通过插件 popup 或 options 页面进行修改，与悬浮框无关。

## 用户故事

1. **作为中文用户**，我在读英文网页时选中不认识的段落，悬浮框自动弹出翻译结果，我能立刻读懂。
2. **作为中文用户**，我看到不理解的术语/人名/事件（比如 "LLM"、"SVG"），切换到「解释」tab，悬浮框用中文告诉我这是什么。
3. **作为注重隐私的用户**，我的 API Key 只存在我自己的 Chrome 里，不经过任何第三方服务器。
4. **作为普通用户**，我不需要知道什么是 API Key、provider，有人帮我配好后我就能用。
